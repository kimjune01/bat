Bug
---
src/preprocessor.rs:expand_tabs uses byte length (text.len()) to advance the
cursor across non-tab text. After multi-byte UTF-8 characters, the cursor
overshoots the visible column position, mis-aligning subsequent tab stops.

Affected:
  - "café\tx" at width 8 →
        master: "café   x"  (3 spaces — 5-byte é counted as 5 columns)
        fix:    "café    x" (4 spaces — é counted as 1 column)
  - CJK fullwidth ("a日\tx" at width 8) →
        master: "a日   x"   (5-column visual but cursor at 4 → 4 spaces)
        fix:    "a日     x" (5 spaces — 日 counted as 2 columns)
  - Control characters ("\x01\tx" at width 8) →
        master: tab counts ^A as 0 cols (correct accidentally) but earlier
                code path could expand it differently in --show-all mode
        fix:    explicit zero-width handling for C0/C1 control chars

Fix
---
Two commits:

  5bedcdab  fix: use column width instead of byte length for tab expansion
            Replaces `*cursor += text.len()` with `*cursor += str_width(text)`,
            where str_width sums unicode_width::UnicodeWidthChar::width per
            char (treating None as 0). unicode-width is already a transitive
            dependency via syntect/etc.

  a019918d  fix: treat control characters as zero-width for tab alignment
            Refines str_width's handling of C0/C1 controls (\x00-\x1f, \x7f),
            which UnicodeWidthChar reports as None. Previously expand_tabs
            assumed width 2 for caret-notation rendering (^A) but bat does
            NOT use caret notation in the non-show-all path, so width 0 is
            correct.
